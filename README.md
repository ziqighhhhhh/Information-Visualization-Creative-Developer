# Information Visualization / Creative Developer 视觉资产库

这是一个**个人视觉资产库**，不是通用前端框架，也不是组件库或脚手架。

## 核心原则

> **先复刻完整页面，再把高复用部分拆出来归档。**

工作流永远是：

1. **复刻**：遇到一个值得学习的可视化 / 创意开发作品，先整体复刻为一个完整、可运行的页面（放 `07-pages/`）。这个阶段允许"脏"，目标是 1:1 还原效果并理解实现原理。
2. **拆解**：确认某部分（背景、动效、地图方案、shader 效果……）在未来项目中会反复用到，才把它从完整页面里抽出来，归档进 `01-layout/` ~ `06-effects/` 对应的目录。
3. **归档**：每个资产子目录是一个自包含单元，包含可运行的最小实现 + 说明文档，让几个月后的自己能直接复制粘贴复用。

**不预先抽象。** 不要为了"以后可能用到"而提前建通用组件。只有真的复用过 2 次以上的代码才值得进入归档目录。

## 命名规则

> **目录名描述稳定能力，CSS / JS / 配置描述可变表现。**

- 资产目录名只写**它是谁**（稳定身份）：`metric-card`、`energy-ring`、`world-map`。
- 不写可变表现：颜色、Dark/Light、Glow、速度、动画方式（CountUp、Fade、Stagger……）都是可换的表现层或行为层，写进 CSS / JS / config 和资产 README，不写进目录名。
- 反例：`metric-card-countup-dark`（countup 是可选行为、dark 是 CSS 样式）、`orange-energy-ring-fast`、`dark-world-map-glow`。
- 变体处理：保持 `index.html` + `README.md` 的简单结构，不为变体提前建目录；确有多个值得保留的 Demo 时，才在资产下建 `demos/`（如 `countup-dark.html`、`static-light.html`）。

## 目录结构

| 目录 | 用途 |
| --- | --- |
| `01-layout/` | 页面布局骨架：全屏画布、分栏、滚动叙事等结构性方案 |
| `02-background/` | 背景层资产：渐变、噪点、网格、动态背景 |
| `03-map/` | 地图相关：底图方案、投影、交互地图样式 |
| `04-effects/` | 视觉效果：shader、粒子、辉光、扭曲等 |
| `05-components/` | 可复用 UI / 数据组件：图例、Tooltip、坐标轴等 |
| `06-animation/` | 动效方案：转场、入场、缓动曲线、滚动驱动 |
| `07-pages/` | 完整页面复刻（所有资产的来源与最终应用） |
| `references/` | 外部参考：灵感来源、教程笔记、技术调研资料 |

每个目录内有 README 说明该目录的归档规范。

## 当前状态

骨架阶段。只包含目录结构与归档规范，暂无具体实现。

## 技术说明

- 本仓库**不预设框架**（React / Vue / Three.js / GSAP 等都不是仓库级依赖）。
- 每个具体资产（如 `04-effects/xxxx/`）如果确实需要某个库，在自己的子目录内以最小方式声明和引用，互不影响。
- 仓库根目录不放构建配置，不写公共基建。
